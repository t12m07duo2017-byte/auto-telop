# 新規顧客追加手順(開発者向け)

新しいお客さんにauto-telopを配布するたびに行う作業。コード本体(器)は一切変更しない。
テンプレのスタイル・SE構成の設計そのものは自動化しない(毎回手作業で判断する)。

## 全体の流れ

1. お客さんの理想とするYouTube動画を見て、合うテキストスタイル・SEの組み合わせを決める
2. そのお客さん専用のPremiereテンプレ(Essential Graphicsスタイル)を作り込む
3. `new-customer` コマンドで顧客フォルダの雛形とライセンスキーを生成する
4. `analyze-template` でテンプレからスタイル一覧を抽出する
5. `style_se_categories.json` を手入力で作る
6. 顧客フォルダ一式(4点セット)を、お客さんへ私的な方法(メール/Google Drive等。
   **公開リポジトリ経由では絶対に送らない**)で送る

## 手順

### 1. お客さん専用テンプレを作る

お手持ちのAdobe Premiere Proで、そのお客さんのYouTubeチャンネルの雰囲気に合う
Essential Graphicsスタイル(基本テロップ・ポジティブ/ネガティブ/強調テロップ)を作り込み、
SE音声ファイルをプロジェクトパネルに配置した `.prproj` を用意する。

### 2. 顧客フォルダの雛形+ライセンスキーを生成する

リポジトリのルート(`auto_telop_pkg/`)で:

```bash
auto-telop new-customer <顧客名> --customers-dir customers
```

これで `customers/<顧客名>/` が作成され、以下が用意される:

- `style_se_categories.json`(空の雛形。後で手入力する)
- `license.key`(このお客さん専用の実行許可キー。署名付き、自動生成)

初回のみ、署名用の秘密鍵が無ければ先に作成する:

```bash
auto-telop gen-signing-key
```

(秘密鍵は `~/.auto_telop/signing_key.pem` に保存される。**絶対にリポジトリへコミットしない**。
表示された公開鍵hexを `src/auto_telop/license_check.py` の `EMBEDDED_PUBLIC_KEY_HEX` に
反映するのは、鍵を新規発行/ローテーションした場合のみでよい。通常は初回セットアップ時に
1度だけ行えばよく、以降の顧客追加では再実行不要)

### 3. テンプレからスタイル一覧を抽出する

1で作ったテンプレを `customers/<顧客名>/template.prproj` として配置してから:

```bash
auto-telop analyze-template \
  --template customers/<顧客名>/template.prproj \
  -o customers/<顧客名>/style_analysis.json
```

### 4. style_se_categories.json を手入力で作る

`customers/<顧客名>/style_analysis.json` の `style_name_to_uid` に並んでいるスタイル名と、
`se_audio_files` に並んでいる音声ファイル名一覧を見ながら、
`customers/<顧客名>/style_se_categories.json` を編集する。

主なフィールド:

| フィールド | 内容 |
|---|---|
| `base_caption_style_name` | 基本テロップ(逐語キャプション)に使うスタイル名 |
| `categories.ポジティブ/ネガティブ/強調テロップ.styles` | カテゴリごとの `{スタイル名: SEファイル名}` 対応表 |
| `category_color_label` | Premiereのビン内での色ラベル(任意) |
| `style_font_name` / `font_paths` | スケール自動調整に使うフォント(省略可) |
| `clear_existing_tracks` | このツール導入前からテンプレに配置済みの古いテロップ/SE等を、生成のたびに削除して空にしたいトラック(例: `{"video": ["V1","V2"], "audio": ["A1"]}`)。このツールが新規に使うトラックには触れないため書く必要はない。不要なら省略可 |

参考実装として `src/auto_telop/data/style_config.example.json`(匿名化済みの記入例)を
見比べながら作るとよい。判断そのものは毎回このお客さんの動画の雰囲気を見て手作業で行う。

### 5. 動作確認する

```bash
auto-telop --customer-dir customers/<顧客名> \
  -s サンプル台本.rtf -v サンプル音声.wav -o test_output.prproj
```

ライセンスキーの検証も含めて最後まで通ることを確認する。

### 6. お客さんへ送る

`customers/<顧客名>/` フォルダ一式(`template.prproj` / `style_analysis.json` /
`style_se_categories.json` / `license.key`)を、メールやGoogle Drive等の私的な方法で
お客さんへ送る。**公開GitHubリポジトリには絶対に含めない**(`.gitignore`で
`customers/*/` は既に除外されている。`git status` で混入していないことを都度確認する)。

お客さんには、`docs/お客様向け手順書.md` の内容を案内し、送った4ファイルを
`customer_package` フォルダに入れてもらう。
